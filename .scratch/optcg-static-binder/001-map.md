# Static One Piece TCG Player Binder — Wayfinder Map

## Destination

A build-ready specification for a public **GitHub Pages** static One Piece TCG player-binder companion site. The site:

- Imports the three supplied CSVs: master collection inventory, a WIP build decklist, and a Sabo-themed decklist.
- Uses **Vega's** local English-Asia card catalog and card images as the data source.
- Models one physical binder: 50 sheets, double-sided, 3×3 grid = **900 pockets**.
- Automatically assigns card-code slots in **player-first order** (color → cost → type), with **reserved slot** space for future cards.
- Supports **search** by card code, card name, page number, and slot position.
- **Checks** imported decklists against the collection inventory and reports availability.

## Notes

- The user wants **Astro** considered as the static-site framework.
- Commits and data updates are rebuilt via **GitHub Actions**.
- Product implementation (actual site code) is explicitly **outside** this planning map.
- The upstream Vega snapshot has both catalog data and images, but the `vegapull` binary is **not available locally**.

## Decisions so far

- **Player-first sorting**: binder slots ordered by color → cost → type.
- **Static local catalog**: Vega snapshot data is checked into the repo or generated at build time; no live API calls.
- **EB03-052 correction**: the Vega catalog has the corrected EB03-052 entry; the empty Sabo total row is ignored on import.
- **900-pocket, one-code-per-slot physical model**: each pocket holds exactly one card code; multiple copies stack.
- **Automatic placement with reserved slots**: algorithm assigns slots; reserved slots are skipped and left empty.
- **Import/check-only decklists**: decklists are updated by editing CSVs and committing; the site only validates against inventory.
- **Public site**: hosted on GitHub Pages with no auth.

## Not yet specified

- Multi-binder support (future).
- Trade/wishlist inventory (future).
- PWA/offline enhancements beyond static assets (future).

## Out of scope

- Product implementation (HTML, CSS, JS, Astro components, build config).
