# Static One Piece TCG Player Binder — Wayfinder Map

## Destination

A build-ready specification for a public **GitHub Pages** static One Piece TCG player-binder companion site. The site:

- Imports the three supplied CSVs: master collection inventory, a WIP build decklist, and a Sabo-themed decklist.
- Uses a **minimized generated Vega catalog** and selected local image assets as its data source.
- Models one physical binder: 50 sheets, double-sided, 3×3 grid = **900 pockets**.
- Automatically assigns card-code slots in **player-first order** (color → cost → type), with **reserved slot** space for future cards.
- Supports **search** by card code, card name, page number, and slot position.
- **Imports** the named decklists solely to reflect physical card locations in search; deck availability checking is excluded from v1.
- **Maintains** a static want-to-buy list whose entries target the binder or a named deck.

## Notes

- The user wants **Astro** considered as the static-site framework.
- Commits and data updates are rebuilt via **GitHub Actions**.
- Product implementation (actual site code) is explicitly **outside** this planning map.
- The upstream Vega snapshot has both catalog data and images. The `vegapull` binary is installed locally via `cargo install vegapull --version 1.2.3`; the raw snapshot lives under `.vega/` (not committed).

## Decisions so far

- **Player-first sorting**: binder slots ordered by color → cost → type.
- **Static local catalog**: Vega snapshot data is checked into the repo or generated at build time; no live API calls.
- **EB03-052 correction**: the Vega catalog has the corrected EB03-052 entry; the empty Sabo total row is ignored on import.
- **900-pocket, one-code-per-slot physical model**: each pocket holds exactly one card code; multiple copies stack.
- **Automatic placement with reserved slots**: algorithm assigns slots; reserved slots are skipped and left empty.
- **Import/check-only decklists**: decklists are updated by editing CSVs and committing; the site only validates against inventory.
- **Strict validation**: duplicate card-code rows fail; invalid rows, codes, or quantities fail with CSV filename, row number, invalid value, and exact reason in error output; only the known Sabo `,51` summary row is ignored; EB03-052 is the deliberate correction and any other malformed code fails.
- **Stored-deck location**: binder quantity is collection quantity minus quantities allocated to each current deck CSV. Cards with spare copies appear in both binder and deck search. Only positive-binder-quantity codes occupy slots; duplicates stack in one slot.
- **Automatic placement/growth policy**: sections Leaders → Red → Green → Blue → Purple → Black → Yellow; within color: cost asc, Character→Event→Stage, code asc. Each color/cost/type group gets three spare pockets. Overflow uses removable sheets added to that color section. Digital Binder view recomputes locations after insert; digital Sorted view always shows ideal order. No routine reshuffle required.
- **Mobile binder/search experience**: Collection is the default mobile-first landing (vertically scrollable player-first browse). Tapping a card opens detail (metadata, owned qty, binder/deck locations); `Show in binder` navigates to and highlights exact Sheet/Side/Slot. Physical Binder is literal 3×3 grid with Front/Back toggle and Previous/Next controls. Search supports code/name with color, cost, type, and location filters. Reserved, no-results, and overflow are explicit states. Pixel 8 Pro (412 CSS px) is the mobile quality baseline.
- **Small buy-list feature**: a static/manual want-to-buy list with binder or named-deck target is in this map; marketplace functionality is excluded.
- **Catalog packaging (accepted risk)**: the user accepts copyright/terms risk of publishing Vega-derived official card data/images on the public noncommercial site. Uses a project-local `.vega/` snapshot bootstrapped via `cargo install vegapull --version 1.2.3` and interactive `vega pull all` (english-asia, `.vega/` output, images yes). Local extraction script generates minimized catalog + only referenced card images. Selected assets only; strict input validation; prominent attribution/unofficial notice required; no Bandai logos or implied endorsement.
- **Public site**: hosted on GitHub Pages with no auth.
- **Astro static build and deployment**: Astro static output, vanilla TS browser modules. Generated JSON + images committed from local extraction; CI never runs vegapull. npm with `package-lock.json`; scripts `generate`/`validate`/`check`/`test`/`build`. CI order: validate → check → test → build, deploy only on all pass. GitHub Pages normal project URL, `site`/`base` Astro config, Pages source GitHub Actions. Workflow `.github/workflows/deploy.yml` on push to main and workflow_dispatch. No PR deployment in v1.
